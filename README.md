# ZakoHeads - Fabric, несколько версий Minecraft

Один репозиторий с независимыми модулями для **1.16.5, 1.20.1, 1.21.4,
1.21.8, 1.21.11, 26.1, 26.2 и 26.3**. Каждый модуль выпускает отдельный JAR
для своей версии игры. Промежуточные версии Minecraft не заявлены как поддерживаемые.

## Сборка

Нужен **JDK 25** для запуска Gradle 9.6. Gradle Wrapper находится в репозитории.
Версия байткода выбирается отдельно: Java 8 для 1.16.5, Java 17 для 1.20.1,
Java 21 для 1.21.x и Java 25 для 26.x.

```powershell
# Только одна версия (остальные модули даже не конфигурируются)
.\gradlew.bat "-Pmc=26.3" build

# Несколько выбранных версий
.\gradlew.bat "-Pmc=1.16.5,1.21.11,26.3" build

# Все восемь версий
.\gradlew.bat buildAll

# Запуск клиента выбранной версии
.\gradlew.bat "-Pmc=26.3" :26.3:runClient
```

На Linux/macOS используйте `bash gradlew`. Готовые файлы находятся в
`versions/<версия>/build/libs/`. Для установки нужен JAR без суффиксов
`-sources` и `-dev`, Fabric Loader и Fabric API соответствующей версии.
Cloth Config включён в JAR; Mod Menu устанавливается отдельно для экрана настроек.

## Структура

- `versions/<версия>/gradle.properties` - Minecraft и версии зависимостей.
- `versions/<версия>/build.gradle` - плагин Loom и подключение общей настройки.
- `versions/1.*/src` - код из исходных веток с отдельными API и mixin'ами.
- `shared/26` - общий код и ресурсы 26.x.
- `gradle/target.gradle` - общие зависимости, ресурсы, Java и имена JAR.
- `settings.gradle` - список целей и фильтр `-Pmc`.

Исходники существующих версий взяты из веток upstream:

Для добавления новой цели создайте каталог в `versions`, задайте зависимости и
добавьте номер в `supported` в `settings.gradle`. Подключайте общий код только
после проверки совместимости Minecraft API; при изменениях используйте собственный
`src` модуля. Само добавление номера версии не обеспечивает совместимость.

## Релизы GitHub

После каждого push в `main` запускается workflow `Release`. Версия берётся из
`mod_version` в `gradle.properties`: для `1.2.1` автоматически создаются тег
`v1.2.1` на отправленном коммите и соответствующий релиз.

Если релиз этой версии уже существует, публикация пропускается без перезаписи.
Для следующего релиза нужно повысить `mod_version` и отправить изменения в `main`.
Отдельно создавать или отправлять тег не требуется.

Workflow использует общую матрицу сборок и публикует релиз только после успешной
сборки всех восьми версий. В релиз попадают 8 JAR мода и 8 JAR с исходниками.
GitHub дополнительно предоставляет стандартные архивы исходного кода ZIP и TAR.GZ.
Название и описание генерирует GitHub, включая ссылку Full Changelog.

Сборки остальных веток, pull request и ручной запуск `Build Minecraft targets`
только проверяют проект и не создают релиз.

Нужны включённые GitHub Actions. Дополнительные секреты не требуются:
для публикации используется стандартный GITHUB_TOKEN с разрешением contents: write.
